An error can become a deferral, and the error ring extends past the route (#810).

- **`recovery.defer(request)`** is a fourth directive an `.error()` handler may answer with, beside recover, drop and rethrow. The failing exchange parks durably instead of ending. The handler names no position: the framework parks re-entrantly at the step that failed, or at position 0 as an admission when the failure came from the pre-from chain, and refuses a position a deferral could never be revived from with `RC5051`. A refusal, a missing deferral runtime (`RC5052`) and a failed store write all stay inside the failure path, so the exchange still reports exactly one terminal event.
- **`notify`** rides the directive and is awaited only AFTER the record is written and `route:exchange:deferred` has fired, the opposite ordering to `deferAside`'s `announce`: a park the framework refuses sends nothing external, and nobody is handed a token for a record that will never exist. It is bounded by the deferring route's own abort signal, and a throw or an abort denies the record claim-first (`RC5067`) so no live resume link survives a notification that did not go out.
- **`ctx.registerHandler("error", handler, selector?)`** and the `handlers: { error }` config key add a third error ring outside the route, so a plugin can decide a failure is recoverable without any route knowing. Handlers run in registration order, the first non-`undefined` return decides, `undefined` passes, and a handler that throws is reported while the chain continues. A route that handles its own failure is never overridden. The optional selector scopes a registration by route id or tag, and a non-matching handler is never called. The fourth argument is an `ErrorContext` carrying `route` and `execution` (`1` on the first run, `2` on a resumed continuation), so a handler that parks does not park the continuation again and ask the same human twice. A three-parameter `ErrorHandler` stays assignable. `HandlerPointRegistry` is declaration-merged, so the three remaining points land as additions rather than a rename.
- **`.resume(mapper, { elevate })`** re-mints the parked principal so a continuation may carry more authority than the exchange parked with, which is what makes a generic step-up possible: refused for a missing scope, park, a human lends the scope, resume, succeed, with no route knowing. `elevate` runs after `authorize` and before the claim, and its result is applied only once the claim succeeds. The principal must be live-branded, it must be the same two parties (everything but `scopes` is compared structurally), and a lend is capped per ring by the scopes the refusal recorded. Anything else is `RC5056`, non-destructive.
- **`InsufficientAuthority.missing` carries `effective`**, whether the gate that refused read the effective ring, so a consent flow can decline to ask a human for a scope that could never open that door. `insufficientAuthorityOf(error)` is exported for reading the refusal off a thrown `RC5038`.
- **Breaking**: `context:error` and `route:exchange:failed` now fire only when nothing decided, so a failure a context handler resolves reaches neither. A subscriber counting `context:error` as "every failure" under-counts once a handler starts deciding.
- **`@routecraft/ai`**: a tool whose own route parks resolves with a `Deferred` acknowledgment carrying a live resume token, which under the default bearer door would let a model resume its own parked act. The bridge records the neutral `DEFERRED_TOOL_PLACEHOLDER` instead, so the token reaches neither the model's context, the session thread nor the telemetry snapshot. The agent's own run does not park on a downstream park.
- **`@routecraft/ai`**: every `agent:*` and `route:agent:*` entry moves out of core's `EventDetailsMap` into this package through declaration merging, the shape the MCP events already used. No event name, payload or emit site changes.
