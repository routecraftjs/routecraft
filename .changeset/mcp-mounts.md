The MCP server over HTTP answers below its path, one mount per name it knows, with nothing to configure. `/mcp` is unchanged. `/mcp/<client>` serves the tools a route proxies from that registered client under the remote's own names, unprefixed, an exact route winning over a star route for its tool. `/mcp/<name>`, the plugin's `name`, serves the application's own tools: the local `.from(mcp())` routes and the exact proxy routes under their exposed names, a local route keeping a name over a proxied tool as at the root. The mounts share `auth`, `cors`, `browserOrigins` and the `tools` filter, which judges a proxied tool by the name the root lists it under on every mount; each mount has its own RFC 9728 document, the root's naming `resource.url` and a mount below it appending its segment; a path below the root that is no mount is a 404. Over HTTP a client id equal to the server name, or a name or client id that is not one path segment, fails the bind with `RC5003`; stdio keeps the single root surface and checks neither. Every `plugin:mcp:tool:*` event carries the segment as `mount` for a call that did not arrive on the root, and `McpToolMount` and `McpToolProvenance` are exported. `McpServer.getAvailableTools(mount?)` lists the tools of one mount.
