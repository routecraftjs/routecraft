The MCP server over HTTP answers below its path, one mount per name it knows, with nothing to configure. `/mcp` still lists everything under the exposed names. `/mcp/<client>` serves the tools a route proxies from that registered client under the remote's own names, unprefixed, an exact route winning over a star route for its tool. `/mcp/<name>`, the plugin's `name`, serves the application's own tools: every local `.from(mcp())` route and every exact proxy route under its exposed name. The mounts share `auth`, `cors`, `browserOrigins` and the `tools` filter, which judges a proxied tool by the name the root lists it under on every mount; each mount has its own RFC 9728 document whose `resource` is `resource.url` with the segment appended; a path below the root that is no mount is a 404. Over HTTP a client id equal to the server name, or a name or client id that is not one path segment, fails the bind with `RC5003`; stdio keeps the single root surface and checks neither. Every `plugin:mcp:tool:*` event carries the segment as `mount` for a call that did not arrive on the root, and `McpToolMount` and `McpToolProvenance` are exported. `McpServer.getAvailableTools(mount?)` lists one mount.
