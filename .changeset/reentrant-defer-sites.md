Re-entrant defer sites: a step can defer the exchange it is executing, own the closure state that revives it, and be denied cleanly when its run is cancelled (#268, #269, #552, #581 groundwork).

The core seam the agent tier plugs into, kept agent-ignorant:

- **`markDeferCapable(adapter)`** brands a `.to()` / `.enrich()` adapter as able to raise a durable deferral from inside its own execution. The defer-site walk assigns such steps a re-entrant `DeferSite` whose continuation includes the step itself, so a resume re-runs the step to finish the work it deferred in the middle of. The step's own definition is therefore covered by the continuation hash: editing it invalidates its deferred exchanges through the `RC5048` re-ask path. The `.split()` / `.multicast()` / `.dispatch()` refusals a static `.defer()` gets at build time apply as recorded refusals that fire on the first actual deferral (`RC5051`), because whether a capable step ever defers is dynamic.
- **`DeferSignal`** is the throwable a branded adapter raises: `{ schema?, ttl?, meta?, callBinding?, stepState? }`. It converts into the ordinary `defer` StepOutcome inside the hosting step, before any step-scope wrapper can observe the throw (a retry wrapper seeing the raw signal would re-run the deferral and charge the work twice).
- **`stepState`** rides `DeferRequest` into the record's existing opaque slot, under the same plain-JSON rule as the exchange (`RC5042`), and comes back through exchange internals (`peekResumeStepState`): the step reads without consuming, the executor clears when the step settles, and a retried attempt still resumes, while a later defer-capable step in the same continuation starts clean. Nothing agent-shaped enters the core record.
- **Validation narrows for re-entrant sites only**: no live `schema` can be read back off the route (it was raised inside the step's own code), so `RC5049` never fires there and the raw payload is delivered to the re-entering step as its deferred call's result. A resume-token holder can therefore hand such a step arbitrary JSON; the step is the validator. Static `.defer()` sites keep full validation.
- **New `deferredSchema` / `DEFERRED_JSON_SCHEMA` exports** give transports a Standard Schema for the acknowledgment, which is what lets the MCP server advertise `oneOf: [Output, Deferred]`. The acknowledgment stays `{ status, deferralId, token, schema?, expiresAt? }`: it crosses the wire, so it carries the contract and nothing policy-shaped.
- **New `RC5054`**: a run cancelled around its own deferral (an elapsed route-scope `.timeout()`) refuses to defer before the store write, or immediately denies the just-written deferral after it, so no live resume link survives a run whose caller was told it failed. A token presented later reads `RC5050`. `context.stop()` is not cancellation: deferred exchanges survive it, which is the store's entire purpose.
