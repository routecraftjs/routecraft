"@routecraft/ai": minor

Talk to a Routecraft agent from your editor, over the Agent Client Protocol (#599, #730, #731, #732).

**`acpPlugin()`** serves the protocol over Streamable HTTP, beside the MCP mount and the HTTP surface, on the same named server and behind the same wall. Nothing ships switched off: installing it serves every agent the context holds, at `/acp` unless `path` says otherwise, and the framework's own name reaches the editor unless `agentInfo` replaces it outright. Options are `path`, `server`, `auth` (the same union `mcpPlugin` takes, `false` to remove the wall), `agent` (the persona a client gets when it picks none), `cors`, `agentInfo` and `toolCallPayloads`. The plugin builds one route per agent when it applies, so it must be listed after the `agentPlugin()` that registers them; an empty registry at that moment fails the build with `RC5003` saying so, rather than serving a protocol with nothing behind it. `@agentclientprotocol/sdk` is an optional peer, loaded through `loadOptionalPeer`, so an app that installs the plugin without it gets `RC5017` naming what to install.

**A conversation is an agent session**, so it outlives the connection, the editor and the instance: closing an editor and reconnecting from another machine reaches the same conversation by its id, `session/load` replays the stored transcript into the editor, one turn runs at a time with the same inbox every other caller of that session gets, and cancelling interrupts the running turn and keeps its partial transcript. **A conversation belongs to the person who started it.** The session record gained `owner`, `cwd` and `title`, and listing, loading and resuming answer only for the caller's own sessions; somebody else's id is answered exactly as a missing one, so probing tells the prober nothing. The management API's listing is deliberately not filtered this way and reports `owner` (replacing the unreleased `startedBy`), because an operator is looking at the instance rather than at their own conversations.

**A person picks the persona, the model and the thinking level** from the editor, through the protocol's config options. An agent file offers a choice by writing a list where it would write a value: `model` and `reasoning` each take an ordered list whose first entry is what the agent runs on, with `models` and `reasoningLevels` as the code-side fields. A control with fewer than two choices is not advertised at all, so an instance with one agent and one model shows no pickers rather than three dead ones; `inherit` inside a list is refused naming the entry; a value outside the advertised list is refused with the new `AI1017`. The persona is changeable only before the first turn, because the session is keyed by the agent it belongs to. The superseded modes API is served alongside the config options for the transition the spec asks for.

**A capability can reach the person's editor.** The new **`surface`** adapter is the one seam for it: `surface(method, params)` is an enricher that asks and waits, which is what an approval is, and `surface.notify(update)` is a destination that tells. Method names and shapes come from the protocol's own generated types rather than being restated, and `sessionId` is filled in from the running turn. It resolves both from the turn's own exchange and, through the correlation id, from a route the turn called, so a capability three hops from the prompt still reaches the person who typed it. `hasSurface(exchange)` is the guard that keeps one route working from an editor and from a schedule alike. Four new codes say which of four different things went wrong: `AI1013` (no surface here), `AI1014` (disconnected mid-turn), `AI1015` (the client never advertised the capability, checked before the call rather than discovered from its silence) and `AI1016` (refused or failed, which is how a person saying no arrives). The framework ships the seam and none of the capabilities that use it: reading a file through the editor is an ordinary route with its own `.authorize()`.

While a turn runs the editor sees token deltas as the model produces them, thinking as thought rather than as text, and every tool call as it starts and when it ends, merged into one stream in order. `toolCallPayloads: false` withholds the arguments and results while keeping the calls themselves visible, which is what an instance serving people other than its operator wants. New events `plugin:acp:connection:opened`, `plugin:acp:connection:closed` and `plugin:acp:session:attached` make the mount observable without reading log lines. Refusals go through the same `bearerChallenge` builder as every other routecraft surface, so a 401 carries the realm and the RFC 9728 `resource_metadata` hint the CLI follows to name the issuer and the missing scope, and rejection log levels match the rest of the codebase: a non-bearer scheme and a stale token are debug, and `warn` keeps meaning a token that failed for a reason worth reading.

`SessionStore` gains `remove(key)`, implemented by both shipped backends. It exists for one case: a conversation that changes persona before its first turn is keyed under the new agent, and the record it came from is dropped rather than left for a bare session id to find. Nothing deletes a transcript, because the persona is only changeable while there is none.

Also on the session runtime: `interrupt(key)` cancels a running turn and reports whether there was one, and a session records the overrides it is running under so a reconnecting editor sees what it chose.
